# Nota Backend

Backend изолирован в этой директории. Команды выполняются из `Backend/`.

```bash
uv sync
uv run alembic upgrade head
uv run uvicorn main:app --reload
uv run pytest
```

API: `http://localhost:8000`, Swagger: `http://localhost:8000/docs`.

## Структура базы данных

Прикладных таблиц только три:

- `users`: имя пользователя и хеш пароля.
- `documents`: название, текст Markdown и владелец документа.
- `document_members`: первичный ключ `id`, внешние ключи `document_id` и `user_id`;
  уникальная пара `(document_id, user_id)` запрещает повторное добавление участника.

Служебная таблица `alembic_version` хранит версию схемы.

Перед обновлением существующей базы сохраните резервную копию и выполните
`uv run alembic upgrade head`. Миграция `0003_documents_only` переносит главы в документы
с сохранением идентификаторов, текстов, владельцев и участников, затем удаляет таблицы
книг, глав и блоков текста. Пустые книги и описания книг становятся отдельными документами.
Иерархия книг и глав упраздняется; автоматический откат этой миграции не поддерживается.
В Docker Compose миграции выполняются сервисом `migrations`.

## API документов

- `GET /documents/` — собственные и доступные пользователю документы.
- `POST /documents/` — создание документа, тело `{"title": "Название"}`.
- `GET /documents/{id}/content` — чтение текста.
- `PUT /documents/{id}/content` — сохранение, тело `{"markdown_text": "Текст"}`.
- `GET /documents/{id}/members` — участники документа.
- `POST /documents/{id}/members` — добавление зарегистрированного пользователя,
  тело `{"username": "имя"}`; доступно только владельцу.

Старые маршруты `/books` и `/chapters` удалены. Участник получает доступ только
к выбранному документу. Изменения видны после повторного открытия документа;
одновременное редактирование в реальном времени не реализовано.

## Сервисы и схемы

SQLAlchemy-запросы находятся в `app/services/users.py` и `app/services/documents.py`.
Сервисы принимают `AsyncSession`, собирают запрос в `stmt` и выполняют его через
`orm_session`. Для записи сервисы вызывают `flush`; транзакцию фиксирует роут.
Ошибки сервисов преобразуются в HTTP-ответы централизованно.

Запросы и ответы описаны Pydantic-схемами в `app/schemas/`. Входные схемы запрещают
лишние поля, нормализуют имя пользователя и проверяют длину и формат значений.
Название документа обрезается по краям, текст документа сохраняется без изменений.
Схемы ответов ограничивают выдаваемые поля; хеши паролей и исходные значения
из ошибок валидации в ответы не попадают. JSON-вход и OAuth-форма используют
одну схему учётных данных. OpenAPI описывает успешные ответы и ошибки.

Миграция `0004_member_primary_key` добавляет отдельный PK участникам, сохраняя связи.
В ответе списка участников `id` остаётся ID пользователя для совместимости,
`membership_id` содержит ID записи участия (у владельца — `null`).
